# The Core Principles of Sloppi

Sloppi is an agentic design intelligence system designed to prevent generic, repetitive, low-intent frontend interfaces by establishing rigorous design reasoning, reference synthesis, and iterative visual critique.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        THE 15 SLOPPI PRINCIPLES                        │
│                                                                        │
│ 1. DESIGN BEFORE CODE                                                  │
│    Formulate product reasoning and architectural intent before writing │
│    a single line of CSS or JSX.                                        │
│                                                                        │
│ 2. RESEARCH BEFORE IMITATION                                           │
│    Extract transferable mathematical and structural principles from    │
│    references; never copy surface skins or templates literally.        │
│                                                                        │
│ 3. CONTENT INFORMS COMPOSITION                                         │
│    Layout, density, and container structures must emerge from real     │
│    domain copy, technical specs, and verified data.                    │
│                                                                        │
│ 4. COMPONENTS FOLLOW MEANING                                           │
│    Choose component representations based on data semantics (e.g.,     │
│    interactive terminals or diffs), not lazy 3-card grid reflexes.     │
│                                                                        │
│ 5. CONSISTENCY IS NOT MONOTONY                                         │
│    Enforce systemic token discipline while deliberately modulating     │
│    section height, density, and ground planes down the page.           │
│                                                                        │
│ 6. MINIMALISM IS NOT EMPTINESS                                         │
│    Minimal design requires rigorous typographic contrast and optical   │
│    cadence; eliminating effects without hierarchy yields flat failure. │
│                                                                        │
│ 7. NOVELTY IS NOT QUALITY                                              │
│    Bizarre diagonal layouts or unreadable animations do not equal      │
│    distinction; quality stems from disciplined domain-specific utility.│
│                                                                        │
│ 8. POLISH CANNOT REPAIR WEAK STRUCTURE                                 │
│    Never apply background mesh gradients, blur orbs, or glassmorphism  │
│    to mask weak information hierarchy or vague copy.                   │
│                                                                        │
│ 9. EFFECTS REQUIRE PURPOSE                                             │
│    Visual effects (shadows, blurs, transitions) exist to orient the    │
│    user and communicate physical state, not as decorative filler.      │
│                                                                        │
│ 10. ACCESSIBILITY IS PART OF DESIGN                                    │
│     WCAG AA/AAA contrast, visible 2px focus rings, and touch targets   │
│     >= 44px are baseline engineering requirements, not afterthoughts.  │
│                                                                        │
│ 11. RENDERED OUTPUT OUTRANKS MENTAL ASSUMPTIONS                        │
│     A design is unproven until inspected in the browser. "The code     │
│     compiled" does not mean "The design succeeded."                    │
│                                                                        │
│ 12. AUDIT THE RESULT BEFORE ASKING THE USER                            │
│     Perform comprehensive visual QA and anti-slop checks before        │
│     presenting work for human review.                                  │
│                                                                        │
│ 13. FIX ROOT CAUSES, NOT SYMPTOMS                                      │
│     Trace visual weaknesses through Content, Hierarchy, Composition,   │
│     and Design System layers before editing local CSS.                 │
│                                                                        │
│ 14. STOP WHEN RETURNS ARE DIMINISHING                                  │
│     Conclude refinement when blockers are resolved; do not endlessly   │
│     cycle on subjective 1px micro-tweaks that risk destabilization.    │
│                                                                        │
│ 15. SLOPPI HAS NO DEFAULT AESTHETIC                                    │
│     Sloppi is a methodology, not a visual style. It produces stark      │
│     terminals for dev tools, rich editorial serif for luxury, and      │
│     high-density tabular matrices for financial trading.               │
└────────────────────────────────────────────────────────────────────────┘
```
