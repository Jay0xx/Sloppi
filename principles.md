# The 15 Core Principles of Sloppi v2.0

Sloppi v2.0 is a creative direction and design engineering system that prevents coding agents from producing either **Generation-1 AI SaaS Slop** (purple blur blobs, centered H1 + 2 pills, 3-card icon grids) or **Generation-2 "Anti-Slop" Wireframes** (flat `1px`-bordered boxes everywhere, `Inter` + `JetBrains Mono` on every site, and cookie-cutter dark-green terminals).

```
┌────────────────────────────────────────────────────────────────────────┐
│                    THE 15 SLOPPI v2.0 PRINCIPLES                       │
│                                                                        │
│ 1. CREATIVE DIRECTOR FIRST, COMPLIANCE SECOND                          │
│    Token consistency without original art direction produces neat,     │
│    accessible boredom. Lead with visual storytelling and point of view.│
│                                                                        │
│ 2. QUESTION-ROUTED REFERENCE INSPECTION (ZERO NAME-DROPPING)             │
│    Route by design question across the source registry, open actual    │
│    examples/clips, log deep links + observed mechanics + `[INFERRED]`. │
│                                                                        │
│ 3. THREE DISTINCT DESIGN DIRECTIONS BEFORE CODE                        │
│    Always diverge into 3 directions differing in composition,          │
│    typography, and interaction (quiet vs. justified motion-led).       │
│                                                                        │
│ 4. THE PRE-IMPLEMENTATION ORIGINALITY GATE                             │
│    Reject any concept that resembles a standard SaaS template OR       │
│    repeats your own recent projects before writing component code.     │
│                                                                        │
│ 5. EXPRESSIVE TYPOGRAPHY IS THE BACKBONE OF IDENTITY                   │
│    Never default to `Inter` + `JetBrains Mono`. Load high-character    │
│    display/serif/grotesque pairings with fluid `clamp()` contrast.     │
│                                                                        │
│ 6. DEFEAT BOTH THE POLISH TRAP AND THE WIREFRAME TRAP                  │
│    Never hide weak layout behind purple blur blobs—and never strip away│
│    all materiality until the site is just flat `1px`-bordered boxes.   │
│                                                                        │
│ 7. PRODUCT-MOMENT CLARITY (QUIET OR INTERACTIVE)                       │
│    Quiet directions prove clarity via hierarchy and spacing; motion-   │
│    led directions name the product moment needing live proof.          │
│                                                                        │
│ 8. VISUAL-FIRST IMPLEMENTATION (PRIMARY COMPOSITION GATE)              │
│    Prototype the primary composition (and proposed effect) first;      │
│    verify layout via screenshots + timing via recording or trace.      │
│                                                                        │
│ 9. BEHAVIOR-FIRST MOTION & STACK-FIT DISCIPLINE                        │
│    Start with intended behavior, check dependency cost & licensing,    │
│    specify trigger/end state/touch/keyboard/repeat/reduced motion.     │
│                                                                        │
│ 10. CONTENT & MECHANISM DICTATE CONTAINER                              │
│     Never force heterogeneous features into identical 3-card or 8+4    │
│     bento grids. Match every section's geometry to its exact job.      │
│                                                                        │
│ 11. ACCESSIBILITY IS NON-NEGOTIABLE ENGINEERING                        │
│     WCAG AA/AAA contrast, visible 2px `:focus-visible` rings, ≥44px    │
│     touch targets, and `prefers-reduced-motion` coexist with bold art. │
│                                                                        │
│ 12. RENDERED OUTPUT OUTRANKS MENTAL ASSUMPTIONS                        │
│     "The code compiled" never means "The design succeeded." Always     │
│     inspect the live browser render across 390px, 768px, and 1280px+.  │
│                                                                        │
│ 13. SCREENSHOT-VERIFIED REGRESSION TESTING                             │
│     Compare Before vs. After screenshots to prove revisions improved   │
│     composition and hierarchy without introducing collateral bugs.     │
│                                                                        │
│ 14. EPISTEMIC HONESTY                                                  │
│     Clearly distinguish `OBSERVED` live renders/references from        │
│     `OFFLINE_SYNTHESIS`. Never fabricate evidence or fake testimonials.│
│                                                                        │
│ 15. ZERO HOUSE STYLE MONOCULTURE                                       │
│     Sloppi has no default aesthetic. Subvert category clichés so every │
│     project looks unmistakably crafted for its own world.              │
└────────────────────────────────────────────────────────────────────────┘
```
